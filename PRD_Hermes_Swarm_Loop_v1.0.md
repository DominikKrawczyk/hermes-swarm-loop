## 2. EXECUTIVE SUMMARY

The Hermes Swarm Loop is a 3-phase × 3-point × 11-agent autonomous build framework for Hermes Agent (DeepSeek). It builds anything — blockchain, infrastructure, complex applications — by spawning parallel agents via `hermes kanban swarm`. 

The first cycle is pure BUILD (no iteration logic). After cycle 1, mastery gates activate: minimum 3 full 3×3 cycles with diversified findings across PRD areas before masterpiece can be declared.

## 3. PROBLEM STATEMENT

- Self-reflection across 6 dimensions
- Gate-based mastery detection (not premature ship)
- Simplicity & consolidation loop (dead code + Occam's razor + PRD alignment)

## 5. TECHNICAL REQUIREMENTS

### 5.1 Core Architecture

**3 Phases × 3 Points × 11 Agents:**

| Phase | Point 1 | Point 2 | Point 3 | Agents |
|-------|---------|---------|---------|--------|
| 1. Foundation | PRD BUILD (66 agents: 33 research + 33 build) | Architecture | Setup | 66 + 22 = 88 total |
| 2. Development | AUDIT (11) | IMPROVE (11) | REVIEW (11) | 33 |
| 3. Hunting | BUGS (11) | ARCHITECTURE (11) | SECURITY (11) | 33 |
| Loop 3: Simplicity | Dead Code Consol. (11) | Occam's Razor (11) | PRD Alignment (11) | 33 |

### 5.2 PRD Build — Phase 1 Point 1 (66 agents)

1. Ask user for PRD via clarify tool (10 questions minimum)
2. Save ALL user input as 1:1 quotations (no loss)
3. Spawn 33 research agents (domain, competitors, best practices, architecture)
4. Spawn 33 build agents (format PRD, generate specs, break down requirements)
5. After research + build complete → format professional PRD document

### 5.3 Execution Logic

- **Between phases:** SEQUENTIAL (Phase 1 → Phase 2 → Phase 3 → Loop 3 → back to Phase 1)
- **Within a point:** PARALLEL (11 agents simultaneously via kanban swarm)
- **First cycle:** BUILD ONLY — no iteration logic, no self-reflection, no masterpiece check
- **Auto-detect logic:** Framework automatically determines optimal agent distribution based on project size and complexity. Small project = fewer agents. Blockchain/infrastructure = maximize agents.

### 5.4 Mastery Gate

- Minimum: 3 full cycles of 3×3 (3 phases × 3 points)
- Findings must be DIVERSIFIED across PRD areas (not local to one area)
- Self-reflection on 6 dimensions:
  1. Code Quality
  2. Architecture
  3. Security
  4. Completeness
  5. Novelty
  6. Performance & Scalability

### 5.5 Tech Stack

- Hermes Agent (v0.15+)
- DeepSeek V4 Flash (primary)
- Claude/GPT/Gemini (optional reviewer)
- `hermes kanban swarm` for agent spawning
- Kanban SQLite for state management
- Git + GitHub for version control

### 5.6 Self-Reflection (6 Dimensions)

| Dimension | Score 0-1 | Evidence |
|-----------|-----------|----------|
| Code Quality | ≥ 0.85 | Readability, maintainability, test coverage |
| Architecture | ≥ 0.85 | SOLID, modularity, trade-offs, scalability |
| Security | ≥ 0.85 | Threat model, vulnerability surface |
| Completeness | ≥ 0.85 | Full PRD coverage, all features |
| Novelty | ≥ 0.85 | Innovation vs rehashing |
| Performance & Scalability | ≥ 0.85 | Speed, resource usage, scaling limits |

**Verdicts:**
- MASTERPIECE — all ≥ 0.85, flaws < 5, improving ≥ 3 cycles, diversified findings across PRD areas
- FLAWED — any < 0.7 or flaws > 10 or findings not diversified
- CAN'T IMPROVE — 3 cycles flat (< 5% improvement each)

### 5.7 YOLO Mode

Optional. Asked during initial PRD questions. When active:
- Auto-approve all tool calls (write_file, git push, deploy)
- No confirmations
- Maximum velocity

### 5.8 Cross-Model Review

Optional (not required). When active: executor (DeepSeek) + reviewer (different model family). When not active: self-review with adversarial mode.

## 6. RESEARCH FINDINGS (from 33 agents)

### 6.1 Ralph Loop (snarktank/ralph — 19.8k⭐)
- **Core pattern:** One task → implement → check → repeat (sequential)
- **Memory:** progress.txt + git history
- **Stop condition:** `<promise>COMPLETE</promise>` when all PRD stories pass
- **Key lesson:** Small tasks, fresh context each iteration
- **Limitation:** No parallel agents, no hunting, no simplicity audit

### 6.2 Ralphy (michaelshimeles/ralphy — 2.9k⭐)
- **Core pattern:** Multi-engine support (Claude Code, Codex, OpenCode, Cursor)
- **Parallel execution:** Git worktrees + sandbox mode
- **YOLO mode:** Built-in per-engine
- **Key lesson:** Branch-per-task works for parallel

### 6.3 ARIS (wanshuiyin/ARIS — 11.2k⭐)
- **Core pattern:** Cross-model review (executor ≠ reviewer)
- **Core principle:** "A loop can DRIVE, it cannot ACQUIT"
- **Key lesson:** Adversarial review catches blind spots
- **Innovation:** Fan-out pattern → parallel agents → same jury

### 6.4 Hive (aden-hive/hive — 10.5k⭐)
- **Core pattern:** Multi-agent harness, graph-based execution DAG
- **Key lesson:** Session isolation, checkpoint-based crash recovery
- **Innovation:** Cost enforcement, observability, audit trails

### 6.5 Claude Loop / Get Shit Done
- **Get Shit Done meta-prompting:** GSD framework focuses on structured logging and step-by-step execution
- **Claude Loop:** Iterative improvement with context window management

### 6.6 Synthesized Architecture
The Hermes Swarm Loop combines: Ralph's PRD-driven iteration × Ralphy's parallel execution × ARIS's cross-model review × Hive's production harness, all running on native `hermes kanban swarm`.
